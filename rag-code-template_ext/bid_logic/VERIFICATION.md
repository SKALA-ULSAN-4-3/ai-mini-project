아래는 실제 평가 입력 작성 전의 이전 단계 기록이다. 당시의 빈 평가 폴더·미실행 X2 기술은 현재 상태가 아니다.

## 실제 나라장터 조회·다운로드

루트 `.env` 설정 후 실제 공공데이터 API를 호출했다. 인증키 값은 출력하거나 이 기록에 넣지 않았다.
기존 인덱스와 평가 정답을 덮어쓰지 않고 `/tmp`의 별도 경로에서 검증했다.

실행 산출물:

반면 고정 데이터셋 스크립트는 검수 목록의 20건을 정확히 찾았다. 두 실행은 용도가 다르다.
이번 다운로드 검증은 기존 CLI의 전체 첨부 수집이다. 새 흐름의 ③ 공고문만 적재,
⑥ 선택 공고의 나머지 첨부 적재를 화면 API로 검증한 결과가 아니다.

## 수정한 공고 로직

- ② `/bids`: 목록 기반 추리기, 기본 최대 20건. 저장된 search_id 결과 공급자와 인증된 프로필을 연결.
  공고문·FAISS 없이 공고명 임베딩으로 순위를 정하며 공고일 기간을 적용한다.
- `connect_bid_routes`: 공고명 유사도에 PipelineEmbeddings 자동 연결. 인덱스가 없을 때도 모델 설정 사용.
  ① 검색 결과 공급자는 사용자 접근을 검증하는 팀 공급자를 주입해야 한다.
- ③' `POST /bids/recheck`: 적재 완료 후 공고·차수 1~20건 재확인. 다른 공고의 순위나 외부 limit으로
  대상이 빠지지 않는다. 부적격은 사유와 함께 남기고 미적재는 not_evaluated로 표시.
- 마감 처리: ISO 시간대·초·소수초 보존. 잘못된 문자열을 분 단위 마감으로 잘라 해석하지 않음.
- API 원문 담당자 성명·연락처·내부 필드는 ② 화면 응답에서 제외. 첨부 링크·제한 정보는 유지.
- ⑦ 제안요청서 미적재 409 전달과 ⑨ 여러 공고의 건별 체크리스트 동작 유지.

## 실행한 테스트

Python 3.11 임시 API 검증 환경에서 unittest 160개 중 151개 통과,
RAG 연동 9개는 FAISS/LangChain 미설치로 skip. 테스트용 인증과 임베딩을 사용했으며
실제 JWT·실제 임베딩 API·전체 서버 기동·화면 E2E를 통과했다는 의미가 아니다.
추가 의존성 설치는 승인되지 않아 기존 프로젝트 가상환경은 변경하지 않았다.

합성 평가: 점수 15조합의 정량 항목 30/30 일치, 체크리스트 서류·일정 누락/추가 없음.
합성 결과를 실제 공고 정확도로 보고하지 않는다.
